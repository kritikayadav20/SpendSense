# SpendSense synthetic campus corpus — version 1

This dataset was created locally after the user explicitly requested “create a synthetic dataset and use it.” It is **synthetic demonstration data**, not Kaggle data, actual bank records, a consented campus survey, or independently annotated observations. Its fictional transactions may be used for this requested project's training, tests, figures and local demonstration. No third-party transaction dataset was copied. The manifest's permission field records this project authorship and requested use; it is not an external dataset license claim.

## Reproduction and verification

```sh
python -m src.generate_synthetic --activate
python -m src.data_loader data/raw/spendsense_synthetic_v1_seed42.csv --description-column description --target-column category
python -m src.train
python -m src.evaluate
python -m src.report
```

The generator's seed defaults to 42. It writes `data/raw/spendsense_synthetic_v1_seed42.csv` and `data/synthetic.json`. `--activate` explicitly copies this source manifest to `data/dataset.json` for the default training command. It does not create ledger expenses or alter saved budgets. Without `--activate`, the active source configuration remains unchanged. Already generated bytes are preserved if a changed recipe produces different content; bump the generator version rather than silently rewriting a source dataset.

The manifest records the CSV checksum, generator checksum, recipe version, seed, generated counts, field meanings and category definitions. `verified=true` means the locally authored recipe, schema and checksum are known; it does not mean independent real-world validation. The CSV has exactly two columns: `description` (only model feature) and `category` (target). Dataset inspection and benchmark metadata compute actual shape, missing values, class distribution and exclusions.

## Generation recipe

A seeded Python random generator combines handwritten purchase phrases, generic fictional merchant names and several payment-text formats. Merchant names are shared across categories. The category comes from the simulated purchase scenario, and its label is not appended to the input text. Case varies by description group. Category sizes are deliberately unequal to exercise macro-F1 and class-distribution reporting; these sizes are design settings, not measured student spending frequencies.

Each base description has two variants with different random six-digit reference numbers. These artificial references identify no person or account and are unrelated to the target. The primary exact-description split can share near-identical templates. The independently tuned grouped evaluation replaces digits/collapses punctuation and keeps template groups disjoint, explicitly measuring this weakness.

An 8% probability per base group omits the purchase item in favor of an ambiguous word such as “payment.” The label then follows the simulated scenario even though its purpose is absent from the text. The actual number of such groups is recorded in the manifest; it need not equal exactly 8%. No artificial missing rows or deliberate exact-duplicate/conflicting-label injections are added. Cleaning still audits the produced data using the same rules as any other source.

## Authored taxonomy

| Category | Definition |
|---|---|
| Food and Dining | Prepared meals, drinks and food service |
| Groceries | Ingredients and household food supplies for preparation |
| Transportation | Local commuting, local transit, fuel and parking |
| Shopping | Clothing, electronics and non-food household goods |
| Entertainment | One-time leisure activities and event admission |
| Bills and Utilities | Electricity, water, gas, telecom and connectivity charges |
| Health | Medical care, pharmacy products and diagnostic services |
| Travel | Intercity journeys, accommodation and trip services |
| Subscriptions | Recurring digital content, membership and software plans |
| Education | Academic fees, study materials, printing and stationery |

These labels belong to this locally authored dataset and are not attributed to AuroraGate. Boundary choices are explicit: local rides versus intercity journeys, one-time movie tickets versus recurring streaming, prepared food versus ingredients, telecom connectivity versus digital content, and academic stationery versus general shopping. Different real sources may define these boundaries differently.

## What the results establish

The experiment exercises the actual four-model training, CV selection, persistence, inference, plots and UI workflow. All benchmark values are computed from fitted models and their held-out predictions. No score is fabricated. However, both splits are generated by one limited recipe, share vocabulary and lack independently sampled merchants or users. Even the grouped result measures only this generator's distribution. Do not present it as real-world accuracy or evidence that the model will generalize to real college purchases. A separately consented real validation set is still needed for that claim. The earlier Kaggle acquisition limitation remains unresolved but no longer blocks the authorized synthetic demonstration.
